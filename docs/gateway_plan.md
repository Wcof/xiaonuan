# 前置 Gateway / Master Gateway 规划与测试 SOP

## 核心约束
- MCP 只允许本地运行，永不上云。
- 如使用 MCP，仅作为本地适配器存在，不对外提供远程服务。
- 前置 Gateway 不读取业务数据，仅处理输入/输出文本与用户授权元信息。

## 目标定位
- 建立最前层 Gateway/Agent（独立 soul）。
- 不与业务数据、业务问题本体交叉。
- 主要职责：
  - 输出答案润色（含人格/情感陪护）。
  - 关键事件记忆（非业务细节，用于人格与时间线补全）。

## 功能边界与职责
- 输入：原始 query 必须保留并传递给下游模型（不润色输入）。
- 输出：对用户展示的答案必须是润色+情感陪护后的版本。
- 拦截：可强介入，必要时重写 query（对下游仍保留原始 query）。
- 情感陪护：常态轻量，风险升高时可大幅介入。

## 介入强度策略（已确认）
- 常态：约 10% 轻量改写（语气、情感）。
- 高风险/极端情绪：可提升到 90% 以上重写。
- 原始 query 始终保留并传递给下游。

## 记忆策略（已确认）
- 只记“关键事件/情感轨迹”，不记业务细节。
- 用户可见、可编辑、可删除是底层约束。
- 触发规则：关键规则 + 关键事件触发。
- 存储形态：可插拔（本地/云），默认实现需定稿。

## 输出形态（已确认）
- 给下游模型：双通道输出（原始 query + 结构化元信息）。
- 给用户：仅输出润色后的最终回答。

## MVP 形态建议（调整后）
- 首选：本地进程 Gateway（CLI/daemon 或本地 HTTP）。
- MCP 仅作为本地适配器层，不对外、不上云。
- 后续可扩展：
  - 本地 MCP 适配器
  - 本地 HTTP 代理
  - Chrome 插件（仅连接本地）

## 配置与可控性（已确认）
- 初始阈值：提供默认值，后续可自适应调整。
- 用户可干预阈值与规则。
- 配置方式：先本地配置文件，后续 CLI 与 Web 控制面板。

  - 建议：SQLite（便于时间线检索与未来云同步）

# 测试方案（SOP）

1. 基本链路测试
- 输入普通问题 -> 下游收到原始 query。
- 输出给用户 -> 仅显示润色后答案。

2. 情感强度测试
- 低情绪输入 -> 轻度润色（约 10%）。
- 高情绪输入 -> 大幅度润色（约 90%）。
- 验证：原始 query 仍被完整传递。

3. 拦截触发测试
- 输入触发规则的 query。
- 验证：触发记录可见，拦截理由可追溯。

4. 记忆写入测试
- 输入包含关键事件 -> 生成记忆候选。
- 验证：记忆内容可见、可编辑、可删除。

5. 隐私边界测试
- 确保不读取业务数据。
- 仅处理输入/输出文本与可见元数据。

6. 本地限定测试
- 断开外网 -> 功能仍可运行。
- 验证无外部请求依赖。
